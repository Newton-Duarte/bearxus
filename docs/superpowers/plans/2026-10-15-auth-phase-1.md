# Auth Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enable GitHub OAuth with persisted users/accounts, JWT sessions, and protected dashboard routes.

**Architecture:** Share a providers-only configuration between the full server auth setup and an adapter-free proxy initialization. Reuse `src/db/auth-adapter.ts`; expose the database user ID through the full configuration's session callback. Add a minimal server-rendered dashboard as the post-login destination, not a dashboard UI feature.

**Tech Stack:** Next.js 16.4 App Router, NextAuth v5 beta, Drizzle, Neon PostgreSQL, TypeScript.

**Spec:** `context/features/auth-phase-1-spec.md`

## Global Constraints

- Use `next-auth@beta`, not `@latest`; the installed `^5.0.0-beta.32` and `@auth/drizzle-adapter` already satisfy the dependency requirements.
- `src/auth.config.ts` contains providers only, no adapter; use `session: { strategy: 'jwt' }` in `src/auth.ts`.
- Proxy lives at `src/proxy.ts` and uses `export const proxy = auth(...)`, not a default export.
- Do not configure custom `pages.signIn`; use NextAuth's default pages.
- Required environment variables: `AUTH_SECRET`, `AUTH_GITHUB_ID`, `AUTH_GITHUB_SECRET`.
- Follow installed Next.js guides and current Context7 documentation (consulted during planning).
- No schema changes, migrations, or production database operations. Any database verification must use development only.
- Project workflow defers unit tests: use browser/HTTP checks, lint, types, and build. Never commit without permission.

## Review Focus

- Nested dashboard URLs and query strings must survive the unauthenticated sign-in redirect.
- Missing, expired, or tampered session cookies must not grant access.
- Auth endpoints and the public home page must remain accessible without redirect loops.
- A returning GitHub user must retain the same database-backed session user ID.
- Missing OAuth configuration or denied consent must not be reported as successful end-to-end verification.

**Interfaces:** Providers-only default export satisfies `NextAuthConfig`; full configuration exports `{ auth, handlers, signIn, signOut }`. Route exports `{ GET, POST } = handlers`. Augmented `Session.user` retains `DefaultSession["user"]` fields and adds `id: string`.

**Interfaces:** Initialize `const { auth } = NextAuth(authConfig)` independently of the database adapter. Export `proxy = auth(callback)` and a static `config.matcher: ["/dashboard/:path*"]`. Dashboard's async default Server Component consumes the full `auth()` from Task 1.
