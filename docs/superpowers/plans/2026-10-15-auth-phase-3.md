# Auth Phase 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add custom authentication pages and a sidebar account dropdown without changing existing authentication or registration semantics.

**Architecture:** Use Server Components for page shells and server-side session reads, with small Client Components for forms, image fallback, and account-menu interaction. Use Auth.js Server Actions for sign-in/sign-out and the existing registration HTTP endpoint for account creation. Stream request-dependent content behind Suspense because Cache Components is enabled.

**Tech Stack:** Next.js 16.4 App Router, React 19.3, NextAuth v5 beta, TypeScript, Tailwind CSS v4, existing Zod schemas.

**Spec:** `context/features/auth-phase-3-spec.md`, clarified by `context/current-feature.md` and the user's request for a dropdown with Profile, Settings, and Sign out.

## Global Constraints

- Preserve GitHub OAuth, credentials authentication, JWT sessions, and session user IDs; no database schema or migration changes.
- Register fields: name, email, password, confirmPassword; submit to `/api/auth/register`; redirect to sign-in on success, without automatic login.
- Avatar: GitHub image when available, otherwise name initials; `Newton Duarte` → `ND`.
- Sidebar avatar opens the dropdown; Profile links to `/profile`, Settings to `/settings`, and Sign out ends the session and returns to `/sign-in`.
- Reference `context/screenshots/bearxus-sidebar-example.jpg`; use restrained dark surfaces and violet account accents, with Bearxus branding. No top-bar avatar.
- Builder scope: add a minimal sidebar to the existing dashboard, not unrelated workspace modules, profile/settings editors, or placeholder pages. Those two menu links target future routes.
- Reuse existing dependencies and validation. Keep Tailwind scanning restricted to `src/`; no Tailwind JS configuration or inline styles.
- All database operations target development endpoint `ep-silent-bird-b59kwhec`; verify the runtime target before auth tests. Never access production or delete test users without permission.
- Project workflow defers unit tests: use failing-then-passing HTTP/browser acceptance checks. Do not commit without permission.

## Review Focus

- Callback URLs from query strings or form data must not send users to another origin or into an auth redirect loop.
- Invalid credentials and OAuth errors need useful, generic messages without exposing account details, tokens, or passwords.
- Registration rejection, network failure, and repeated submission must leave a usable form and never imply success.
- Missing names, whitespace-only names, and broken avatar images must produce a stable, accessible fallback.
- Keyboard users must be able to open and dismiss the dropdown, reach every action, and regain trigger focus after Escape.
